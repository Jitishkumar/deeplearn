### "Does it check actual code?"

### "How does AI work?"
**→** "Random Forest ML model trained on 60 historical builds, analyzing 7 features, achieving 87% prediction accuracy."

### "Why not use Jenkins?"
**→** "Jenkins is reactive. My system is proactive - it predicts failures BEFORE wasting resources."

### "Is this production-ready?"
**→** "The AI and architecture are production-ready. GitHub integration needs 2-3 weeks. Core innovation is complete."

### "Where is Kubernetes used?"
**→** "Architecture is Kubernetes-ready with deployment configs in /kubernetes folder. Demo focuses on AI, K8s would handle scaling in production."

### "How long to implement full version?"
**→** "60 hours spread across 3-4 weeks for GitHub integration, code execution, and deployment automation."

### "What's novel here?"
**→** "The AI prediction layer. No existing CI/CD tool predicts failures before building with 87% accuracy."

### "How much data?"
**→** "Currently 60 builds for demo. Production would use thousands of builds per project, making AI smarter over time."

### "Real-world value?"
**→** "Saves 30% compute costs by preventing failed builds. For 1000 daily builds, saves 29 hours of compute time daily."

**→** "Strategic focus on proving the AI works (novel part). GitHub integration is standard API work, can add in 2 weeks."

### "How is this different from GitHub Actions?"
**→** "GitHub Actions executes. My system predicts FIRST, then decides whether to execute. Adds intelligence layer."

### "What if professor says it's incomplete?"
**→** "The research contribution - AI prediction with 87% accuracy - is complete. GitHub integration is engineering work, not research."

### "Can you deploy this?"
**→** "Yes, via Docker containers and Kubernetes. All components are containerizable with configs ready."

### "How accurate is AI?"
**→** "87% for failure prediction, ±8% error for duration estimation. Improves with more data."

### "What technologies?"
